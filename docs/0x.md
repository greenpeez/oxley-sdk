# 0x Source Integration

Oxley is an exact-input bonding-curve DEX source. This integration uses 0x's
ordinary ERC-20 approval-and-call BASIC action. It does not require a new 0x
callback, hook, authenticated taker getter, custom API or Oxley allowlisting.

## On-Chain Interface

```solidity
function quoteBuy(bytes32 marketId, uint256 amountIn, address caller)
    external view returns (uint256 amountOut, uint256 feeAmount);
function quoteSell(bytes32 marketId, uint256 amountIn, address caller)
    external view returns (uint256 amountOut, uint256 collateralOut, uint256 feeAmount);
function buy(bytes32 marketId, uint256 amountIn, uint256 minAmountOut, uint256 deadline)
    external returns (uint256 amountOut);
function sell(bytes32 marketId, uint256 amountIn, uint256 minAmountOut,
    uint256 minimumCollateralOut, uint256 deadline)
    external returns (uint256 amountOut, uint256 collateralOut);
```

Quote for the **actual executor**. Only routes with `collateralOut == 0` are
supported; encode `minimumCollateralOut = 0`. The pool/target is the curve. Token
pairs and market IDs come from the activation event and registry. Both on-chain
quote methods work without balance/allowance. A Solidity sampler can use the
included `IOxleyCurve.sol`; JavaScript is optional.

## BASIC Encoding

```ts
import { buildZeroExBasic } from '@oxley/sdk/0x';
const action = buildZeroExBasic(swapQuotedForExecutor, 1_000_000);
// Insert action.data into the provider's normal route.
```

| BASIC field | Value |
| --- | --- |
| `sellToken` | This leg's input token |
| `ppm` | Fraction of the executor's current input-token balance; 1,000,000 = 100% |
| `pool` | Manifest curve address |
| `offset` | **36 bytes**, the second ABI argument after the four-byte selector |
| `data` | SDK buy/sell calldata, including minimum output and deadline |

The executor approves the curve, the curve pulls input and sends output back to
the executor. The provider's existing settlement then pays the recipient. The
provider must quote the actual amount selected by its balance and proportion.
BASIC changes only amount-in, not the encoded minimum-output. Do not reuse a
full-size quote for an arbitrary split size. For sequential fills of the same
market, simulate the complete route since earlier fills change its curve state.

The SDK does not hardcode a Settler address, generate Permit2 signatures, or
pretend a BASIC action is a top-level user transaction. End users must approve
the spender specified by 0x's normal allowance mechanism, never blindly approve
Settler. SDK `buildApprovals` is for a direct caller approving the curve, not for
constructing 0x's user funding transaction.

## Newer Curves And Fees

Gen3 and Gen8 curves require the immediate caller to have accepted the Oxley terms (the
executor, for a BASIC route) while the registry enforces them, and Gen8 sells have four
arguments and no collateral leg. The SDK encodes the right call for the quote's market
generation, so `buildZeroExBasic` works unchanged on any of them; resolve the market with
`createOxleyMarkets` and see [current markets](markets.md). Integrator fees from
[integrator fees](integrator-fees.md) are separate token transfers sent by the user's wallet and are
not part of a BASIC action.

## Rewards And Acceptance

The verified curve identifies the immediate caller as the buyer. Generic 0x
routes therefore identify its executor, not the end user. Full ordinary fees
and reward-pot funding remain enforced. End-user reward attribution is not a
claim of this SDK and is not an integration prerequisite.

The local suite exercises the pinned upstream BASIC action, including split
fills, multihop settlement and rollback after a failing final minimum. It does
not establish that 0x has enabled Oxley in its hosted routing engine or that an
Elysium-specific executor has been validated. 0x still performs its normal DEX
source onboarding. User-confirmed Elysium chain availability at launch does not
by itself activate an individual liquidity source.
